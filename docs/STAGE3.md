# Stage 3 — AI video processing and clip rendering

## Implemented

The Stage 2 queue scaffold now runs a resumable worker pipeline. A user-authorized video upload creates a normal project/job; Celery performs work outside HTTP requests and persists progress, stage state, error codes, and artifact checkpoints.

1. **Source validation and audio extraction** — FFprobe verifies the source. FFmpeg extracts the first audio stream to temporary 16 kHz mono PCM WAV, resamples and loudness-normalizes it, preserves the source duration/timeline, and returns a specific `missing_audio` failure for silent videos rather than fabricating a transcript.
2. **Provider-independent transcription** — OpenAI Whisper API and local faster-whisper adapters use automatic language detection and timestamped segments. Provider-supplied word timestamps are retained; missing word timestamps remain null. Segments are validated against media duration and persisted as transcript rows plus JSON artifacts. Audio hash/provider/model keys enable transcript reuse.
3. **Modular LLM analysis** — OpenAI, Gemini, and Claude HTTP adapters request structured JSON. Invalid JSON/schemas/timestamps are retried once; valid clips must meet configured duration limits and source bounds. Each gets component scores (hook 20%, emotional 15%, information 15%, storytelling 15%, context 15%, retention 10%, ending 10%); the weighted 0–100 score is an estimated engagement rubric, **not** a probability of going viral. Duplicate/overlapping candidates are filtered. Analysis artifacts cache by transcript, provider/model, and clip settings.
4. **Speaker/face tracking and crop planning** — OpenCV samples frames rather than processing every frame, Haar face detection is the built-in fallback, and a MediaPipe Face Detection adapter is used when that optional package is installed. Face boxes are associated into tracks; lower-face motion and track evidence are conservative heuristics, not guaranteed active-speaker recognition. Uncertain/multiple-speaker cases use center-crop fallback rather than selecting the largest face. Crop samples and track data are persisted.
5. **9:16 reframe and captions** — Landscape footage is cropped, not stretched. Tracked horizontal crop movement is smoothed and rendered via OpenCV frame crops piped into FFmpeg; static fallback uses the FFmpeg crop/scale filters. ASS supports Classic, Creator, Minimal, Dynamic, and Custom styles, two-line wrapping, safe defaults, word-by-word highlighting only when real word timings exist, phrase-level captions otherwise, font/size/colors/background opacity/outline/position/animation/words-per-line settings.
6. **Rendering and validation** — FFmpeg creates H.264/AAC MP4, 1080×1920 default, configurable FPS/bitrate, burns captions, and keeps audio optional/synchronized. Watermark rendering supplies an explicit system font path; the backend container installs DejaVu Sans for this purpose. It writes a temporary render then validates dimensions, portrait orientation, codec, duration, and file integrity with FFprobe before setting the clip to completed. It also makes a thumbnail and low-resolution vertical preview.
7. **Persistence and results** — Original media, extracted audio, transcript JSON, AI analysis JSON, tracking coordinates, ASS, renders, previews, and thumbnails use the storage adapter. Local is the development default; S3-compatible buckets/endpoints are supported with a shared local worker cache. Results APIs are owner-scoped and return only stored clips. The UI includes score components, timestamps, duration, category sorting/filtering, portrait preview, download, title/time/caption edit-and-rerender, and multi-select ZIP download.
8. **Independent stages and recovery** — `python -m app.processing.cli JOB_ID STAGE` executes one stage after its prerequisites have been persisted. Celery retries transient/unexpected failures; completed stages and their artifacts remain available for retry. A failed worker never promotes an unvalidated output.

### Configuration

See `.env.example`. Main controls include `TRANSCRIPTION_PROVIDER`, `WHISPER_MODEL`, `WHISPER_DEVICE`, `WHISPER_MODEL_CACHE`, `AI_PROVIDER`, `AI_MODEL`, `PROCESSING_MAX_CLIPS`, clip-duration limits, frame-sampling interval, render size/FPS/bitrate, and `STORAGE_PROVIDER` plus S3 bucket/endpoint/credentials. Set provider keys server-side only. Local faster-whisper requires its model files to be present/downloadable in the configured cache. The optional MediaPipe package is not required for Haar fallback.

## Explicit limitations / not verified

- **No provider credentials or model weights were available in the sandbox.** There was no live OpenAI Whisper API, faster-whisper model inference, Gemini/Claude/OpenAI analysis, genuine speech transcript, or real transcript-driven clip selection. These integrations are implemented but live end-to-end provider behavior, quotas, model naming/retirement, and billing are not verified. Until configured, a real job will fail with a clear provider/model error; it will not generate fabricated clips.
- The sample source is synthetic (not a creator interview), and the pipeline integration stubs the ASR/LLM outputs. The full acceptance sequence with genuine long-form speech has therefore **not** been demonstrated.
- Face detection is sampled OpenCV Haar by default; MediaPipe is optional and was not installed/tested here. Mouth motion is only a weak visual signal. Pyannote/audio diarization, reliable active-speaker identification, split-screen conversation layout, and a manual crop-coordinate editor are not implemented. Users can edit timestamps/title/caption settings and rerender.
- OpenAI/Gemini/Claude HTTP adapters were not exercised against live services. Provider usage is recorded as audio seconds/request counts, not a monetary cost estimate.
- S3 behavior is unit-tested with a fake client only. No real AWS/R2/MinIO credentials were supplied. API/worker require a shared media/cache volume when running multiple local-cache S3 workers; production-grade distributed cache/cleanup policy still needs deployment design.
- GPU mode is configured through faster-whisper device settings with CPU fallback, but no GPU was available. Long transcripts above the safe analysis context limit fail clearly rather than being chunked. Storage-capacity enforcement and a scheduled cleanup/retention worker need production hardening.
- Docker Compose/PostgreSQL 16 was not launched. The existing PostgreSQL 18.6 check was from Stage 2 and does not establish Stage 3 compatibility on the Compose version. Browser-driven visual testing was not run.
- Billing remains out of scope, as requested. YouTube stays metadata/reference-only and never downloads a video.
